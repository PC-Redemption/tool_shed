Workspace work-level actions

Use the optional tracked work/tool-shed.yaml file to add ordered project-specific actions around one selected endpoint—or explicitly replace that endpoint's default behavior.

Configure one canonical endpoint

Schema version 1 supports work_model: combined or split, optional target names, and work1 through work5 entries under work_levels. Each level accepts block lists named before and after, plus the boolean run_default.

schema_version: 1
work_model: split
development_target: staging
production_target: production
work_levels:
  work3:
    before:
      - Run the workspace-specific data refresh
    run_default: true
    after:
      - Publish the workspace-specific handoff report
  work4:
    run_default: false
    after:
      - Run the workspace's controlled publication flow

No configuration is the default. If the file or selected level is absent, standard Tool Shed behavior remains unchanged.

Add actions before and after

  1. Run before actions in declaration order.
  2. Run the standard cumulative endpoint unless run_default: false.
  3. Run after actions in declaration order.

Aliases resolve first: ts:work, ts:freeze, ts:push, and ts:ship select work2, work3, work4, and work5. Only the selected endpoint's envelope runs. Lower-level envelopes do not repeat because the default endpoint is already cumulative.

Replace default behavior deliberately

Set run_default: false only when the declared actions replace the selected endpoint's normal behavior. A replacement must contain at least one before or after action. Removing the level entry restores its standard behavior.

Add versus replace: omit run_default or set it to true to wrap the default. Set it to false to suppress that endpoint's standard cumulative actions.

Resolve and validate before execution

Installed snapshots use the workspace-local helper:

python3 tool_shed/scripts/work_level_config.py --workspace . resolve work3 --jsonpython3 tool_shed/scripts/work_level_config.py --workspace . validate --json

In the canonical Tool Shed development checkout, omit the tool_shed/ prefix:

python3 scripts/work_level_config.py --workspace . resolve work3 --jsonpython3 scripts/work_level_config.py --workspace . validate --json

Validation rejects unknown keys, aliases under work_levels, invalid booleans or indentation, empty actions, symlinked configuration, and empty default replacements.

Authority, credentials, and upgrades

Configuration is not an authority grant, credential store, shell-hook runtime, or deployment framework. It cannot broaden the current goal, bypass protected-environment approvals, waive destructive-action safeguards, hide production coupling, or make an unverified outcome complete. Keep credentials out of the file and use existing project tooling and runbooks.

Installation validates an existing declaration before mutation and never creates or overwrites it. Snapshot upgrades preserve its bytes as owner-authored work; invalid configuration causes convergence to fail and roll back instead of partially updating the workspace.
