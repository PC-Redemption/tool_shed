Using Tool Shed commands

Commands are prompt routes for a workspace-capable AI agent. They are not shell commands, and Tool Shed does not require a separate application server.

Put one route at the start

ts: <request>

The ts: prefix tells the active agent to use the workspace-local Tool Shed for the rest of that request. It applies only to that message and does not carry into the next one.

Keep speaking normally

The prefix does not replace ordinary language. State the outcome, relevant constraints, and desired execution endpoint when one matters.

ts: plan the documentation refresh, then work3

Use ts: help for a concise use-case menu, ts: commands for the full command inventory, and ts: help campaigns for focused explanation.

Persistent autonomy removes ceremony, not boundaries

Use ts: autonomy 0 through ts: autonomy 5 to persist the current project's cumulative Observe, Plan, Build, Checkpoint, Collaborate, or Deliver level. Exact numeric ts: approve <level> is an alias. Covered faithful actions continue automatically with fresh internal tokens. Commands never bypass repository policy, safety controls, credentials, protected environments, the requested endpoint, or provider policy.

Common misuse

Do not combine unrelated destinations under one ambiguous prefix, assume a route persists to later messages, interpret autonomy as permission to invent work, or interpret a work level as broader authority than the goal itself.
