Program roadmaps

A roadmap orders outcomes, milestones, gates, and rolling-wave campaign planning for work that spans multiple dependent stages.

Direction without false certainty

Use a Program Roadmap only when a project map needs approved phases, milestones, evidence gates, or multiple dependent campaigns. Standalone maps and campaign queues remain valid for smaller work.

PRM means Plan → Roadmap → Milestone. It names the full outer coordination lifecycle from understood intent through roadmap direction and successive evidence-gated milestone waves. An optional Brainstorm / Idea Brief Discovery Cycle can precede it. ts: prm <outcome> or ts: prm idea <id-or-path> requests end-to-end continuation without bypassing exact approvals or authority boundaries.
Roadmaps provide direction. They answer how the project can get from its current condition to the intended result.

Develop, approve, derive

The Program Cycle owns roadmap direction; each Milestone Wave Cycle derives and runs one evidence-gated slice before returning control to the program.

  1. Develop the roadmap from current project evidence without writing.
  2. Propose an exact revision and review its milestones, gates, decisions, and authority boundaries.
  3. Approve only the unchanged proposal token.
  4. Derive a campaign plan for one milestone, then separately approve that exact plan.
  5. Review computed progress and source drift as campaigns produce evidence.
ts: develop roadmapts: derive campaigns for milestone M1

Reality may revise the map

Campaign evidence can contradict assumptions, expose a missing dependency, satisfy a gate, or make a milestone unnecessary. Review proposes revisions; it does not silently rewrite approved intent.

Common misuse

A roadmap is not a fixed schedule, an automatic campaign factory, or permission to execute every candidate task. Roadmap approval and campaign-plan approval are separate authority boundaries.

Completion is evidence-backed

A milestone is complete when its defined outcome and evidence gate are satisfied by linked work—not when a date passes or a list is exhausted. Project completion requires the intended result to work and be verified.
