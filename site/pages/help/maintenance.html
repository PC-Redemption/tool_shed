Installation and maintenance

Tool Shed installs into a project as portable machinery while project-specific plans and evidence remain owned by that project.

Keep machinery and project work separate

The workspace-local Tool Shed directory contains reusable rules, templates, and scripts. Root work/ contains the project’s tracked coordination state. Current product truth belongs in project docs and code.

An installed Tool Shed is a disconnected snapshot: it is not a Git submodule and must not be used to push changes back to the canonical repository.

Use the guarded updater

ts: fulltsupgrade

The full-upgrade route verifies the latest published release, preserves owner-authored work, converges documented Tool Shed-owned structure, validates provider guidance, and rolls back after a failed post-install check. It refuses modified or unmanaged installations rather than overwriting them.

The phase-one SQLite substrate keeps its database, lock, and rolling backups ignored and local to one worktree. Current protocol 3 updates may establish that ignore boundary but do not initialize, migrate, restore, or remove database state; those operations require a separately qualified database-aware updater.

A version or update-status request is read-only and does not authorize replacement.

ts: versionts: check for updates

Validate in proportion to the question

ts: doctor

Use the read-only workspace doctor when several validators may pass independently while indexes, campaign transitions, or durable evidence remain inconsistent. It returns one health verdict and distinguishes internal consistency from external/runtime truth. Strict mode fails unless the workspace is fully healthy; token-bound repair can regenerate deterministic indexes only.

ts:check focused

Use spot or focused checks for bounded questions. Full validation is appropriate for a frozen candidate, repository policy, or broad impact. Release checks and production verification belong to delivery work that explicitly includes them.

Common misuse

Do not run an update from inside a stale installed snapshot, overwrite owner work to fix topology, treat doctor repair as semantic reconciliation, or assume a clean command exit proves a deployed service is healthy.

Preserve concise evidence

Keep small manifests and summaries versioned. Raw captures, large logs, dumps, screenshots, and generated test payloads belong in ignored evidence directories. Public documentation must not expose credentials, private workspace state, internal network details, or private project information.
