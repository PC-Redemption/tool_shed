Resume

Existing and interrupted work

Tool Shed preserves enough durable context to resume without relying on chat history or inventing a project history that was never recorded.

Read before inferring

In an unfamiliar repository, inspect its root instructions, README and settled documentation, source and test surfaces, then the generated work index and active artifacts. Use machine-readable indexes only when automation needs them.

ts: orient me

Keep observed facts separate from inferred direction. Repository code and current docs outrank stale planning prose.

Resume from durable state

Reconcile the queue before selection, identify the working campaign and current constraint, and continue from the next concrete action. Do not restart finished stages solely because the prior conversation is unavailable.

If work is blocked, name the decision, dependency, permission, credential, or external change required. If the blocking condition clears, unblock first; starting is a separate transition.

Onboard existing projects without rewriting history

Install the work tree, inspect actual project surfaces, then default to a project map and inventory before backfilling detail. Create only useful current-state artifacts. Tool Shed machinery remains a disconnected snapshot; project-specific work stays in the project’s root work/.

ts: onboard this existing project

Common misuse

Do not infer past decisions, populate every available template, or treat an installed Tool Shed snapshot as a checkout for upstream development.

Review planning drift explicitly

ts: review work state

Look for orphaned, stale, or undisposed work and compare planning with current source. Reconciliation reports what can be repaired mechanically and leaves semantic decisions with the owner.
