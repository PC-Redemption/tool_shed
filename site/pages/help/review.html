Review and completion

Review compares the actual result with the intended outcome. Completion is an evidence-backed condition, not a signal that activity ended.

Keep outcome and constraint visible

The Evidence Loop observes, acts, verifies, and adapts inside the current campaign. After each material action or observation, compare actual state with expected state. When they differ, update assumptions, the plan, and the next action before continuing. A successful command is evidence, but it may not prove the user-visible outcome.

Completion belongs to the intended result

Compiling, passing a unit test, finishing a prompt, deploying a container, or ending one campaign may be necessary. None is sufficient by itself unless it satisfies the stated outcome and its completion gate.

  • Focused checks cover the changed behavior.
  • Broad checks are added when scope, policy, or concrete risk justifies them.
  • Delivery claims are verified in the actual target environment.
  • Documentation reflects the behavior that now exists.

Keep large initiatives closed-loop

When a major migration must be governed before its target runtime exists, a tracked bootstrap closure manifest can bind the accepted requirements, design decisions, material changes, evidence, migration obligations, upgrade targets, and exact gate verdicts to stable project and source state. A completed campaign may satisfy one gate while later gates remain explicitly open and release-blocking.

Lifecycle, outcome verdict, and reconciliation state stay independent. A historical loop can be terminal, partial, and reconciled when the comparison is complete but missing source history is explicitly preserved; reconciliation never changes “unknown” into “satisfied.”

Changes after the baseline are appended with stable IDs and named evidence reruns. They are not erased to make the delivered result resemble the original plan. Full validation checks structural and source consistency; release validation requires the declared final closure.

Evidence chooses the next move

A review may accept the outcome, create a focused follow-up, select the next ready campaign, or propose a roadmap revision. Contradictory evidence should change the plan; it should never be hidden to preserve an obsolete sequence.

Reality is allowed to change the roadmap. The revision remains explicit and owner-governed.

Closeout preserves continuity

Report what changed, verification performed, target state, assumptions or discrepancies, and remaining maintenance concerns. Durable artifacts move to completed history; settled current truth belongs in project documentation.
