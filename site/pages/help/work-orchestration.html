Automate the routine

Scripted work orchestration

Direct Work1 and Work2 use one thin runner for deterministic preparation and closeout, leaving model time for product reasoning and real exceptions.

Compose what Tool Shed already trusts

The runner calls the existing identity, work-level, document, validation, checkpoint, Doctor, and release-cohort surfaces. Those commands stay independently callable. The runner is coordination, not a second workflow engine or state authority.

One fixed, inspectable phase graph

Prepare

Verify project and state, resolve the requested endpoint, refresh disposable lifecycle views, and run the existing changed-path validation profile.

Close out

Verify the committed candidate, require current target evidence at Work2, register release ownership, checkpoint and rebuild state, commit only that checkpoint, and require a healthy Doctor result.

Resume from evidence, not optimism

Each mutation starts from an exact project-bound plan token. A completed local phase is skipped only when its run ID and input digest match. Identity, state audits, strict Doctor, and current external evidence always rerun. A local lock prevents duplicate writers.

Failure stays diagnosable. The success envelope is compact; failures retain the phase ID, input state, bounded diagnostic, recovery route, timing, and retry count in ignored local telemetry.

Estimate honestly when exact usage is unavailable

Local events distinguish reasoning, deterministic scripts, recovery, and external waiting. Exact remedial token totals appear only where a provider exposes trustworthy usage, beside measurement coverage. A separately labelled deterministic estimate covers the unmeasured portion using output bytes, tool calls, active duration, and retries; it includes a range, confidence, method version, and calibration state. GUI-native actual usage remains unknown, never zero.

The estimate is directional rather than billing-grade and is never relabelled as actual usage. Existing retained events are estimated at report time without rewriting history. The dashboard aggregate is per-project, versioned, bounded, and sanitized. It contains no prompts, commands, paths, source, or raw diagnostics. Dashboard availability never blocks local work.

Keep semantic authority outside the script

The runner cannot implement behavior, decide whether evidence is sufficient, choose a version or deployment scope, perform deployment, push, release, or close an owning outcome. Work1 and Work2 remain the selected stopping points.
